# HIL Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an HIL teleoperation mode that preserves the current robot pose and expose it from the Qt Mode Manager.

**Architecture:** `ur5e_mode_manager` receives a `hil` request, applies the existing safe switch sequence, then starts a dedicated managed `pika_teleop` process with `reset_before_teleop:=false`. The Qt panel publishes `hil` through the existing mode-request topic and renders service control plus five modes in a fixed six-button grid.

**Tech Stack:** ROS 2 rclpy/rclcpp, Python pytest contract tests, Qt Widgets, CMake/colcon.

## Global Constraints

- `teleop` launches `pika_teleop` with `reset_before_teleop:=true`; `hil` launches it with `reset_before_teleop:=false`.
- Every mode transition retains HTTP ownership revocation, motion cancellation, `/joint_states` stop confirmation, and process cleanup.
- Qt only publishes a `std_msgs/String` mode request; it does not start `pika_teleop` itself.
- The action grid is two equal-width columns and three rows: `Start|IDLE`, `AUTO|API`, `TELEOP|HIL`.
- The service action reads `Start` or `Stop`; no status label shares its action row.
